**Goal:** whale-erp-api 의 직원 계정 인증 API 로 로그인 · 접속 유지 · 로그아웃 · 비밀번호 재설정(핀) 화면과 임시 홈을 만든다.

**Tech Stack:** Next.js 16.3.3 App Router(proxy.ts · 서버 액션 · `useActionState`), React 19.2, Tailwind 4, `openapi-typescript`(타입 생성), pnpm 11.

**Spec:** `docs/plans/2026-10-08-직원-앱-인증-화면.md`

## Global Constraints

- pnpm 전용. pnpm 이 PATH 에 없으면 `export PATH=~/.local/share/pnpm/bin:$PATH`.
- Next 16 은 학습 데이터와 다르다. 새 API 를 쓰기 전에 `node_modules/next/dist/docs/` 의 해당 문서를 읽는다(proxy: `01-app/03-api-reference/03-file-conventions/proxy.md`, 폼: `01-app/02-guides/forms.md`).
- 모든 API 호출은 서버 사이드. `request()`(`src/lib/api.ts`)가 유일한 fetch 경로. `API_BASE_URL` 은 호출 시점에 읽는다.
- 서버 액션 오류: `ApiError` → 폼 상태, `TypeError` → 「서버에 연결하지 못했습니다. 잠시 뒤 다시 시도해 주세요」, 그 밖은 다시 던진다. `redirect()` 는 try 밖.
- 네이밍: 라우트 · 파일 kebab-case, 컴포넌트 PascalCase, API 함수 · 서버 액션은 동사 + 자원, 이벤트 핸들러 `handle*`, 약어 금지(`id`·`url` 등 예외만).
- enum 한글은 `getEnum(name)` + `labelOf()` 로. 상수 대응표 금지.
- 디자인: 화면은 `StaffRoot` 안. 공통 부품에 `className`·`style` 을 넘기지 않는다. 색은 `--color-staff-*` 토큰, 한 곳에만 나오는 색은 직접 적고 주석. 입력칸 글자 16px 이상, 누를 것 44px 이상, 주 동작 52px.
- 핀 · 이메일 · 토큰을 URL · 로그에 넣지 않는다.
- `src/app/demo/**`, `src/app/design/**` 는 고치지 않는다.
- 커밋 메시지: 영어 type 접두 + 한글 제목, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Plane 건 번호를 제목 끝에 `(WHALEERP-165)` 처럼 단다.

```ts
import type { components } from "./api-types";

/** api 가 커밋한 openapi.json 에서 만든 요청·응답 모양(pnpm openapi:types). */
export type Schemas = components["schemas"];

export class ApiError extends Error { /* 그대로 */ }

function baseUrl(): string { /* 그대로 */ }

export interface RequestOptions {
  method?: string;
  /** 본문. 있으면 JSON 으로 보낸다. */
  json?: unknown;
  /** 있으면 Authorization: Bearer 로 보낸다. */
  accessToken?: string;
  /** 모두에게 같은 응답(enum)만 초 단위로 캐시한다. 없으면 캐시하지 않는다. */
  revalidate?: number;
}

export async function request<T>(path: string, { method = "GET", json, accessToken, revalidate }: RequestOptions = {}): Promise<T> {
  const headers = new Headers();
  if (json !== undefined) headers.set("Content-Type", "application/json");
  if (accessToken) headers.set("Authorization", `Bearer ${accessToken}`);

  const response = await fetch(`${baseUrl()}${path}`, {
    method,
    headers,
    body: json === undefined ? undefined : JSON.stringify(json),
    // 사용자마다 다른 응답이라 기본은 캐시하지 않는다. cache 와 revalidate 를 같이 주면 둘 다 무시되므로 하나만 준다.
    ...(revalidate === undefined ? { cache: "no-store" as const } : { next: { revalidate } }),
  });

  if (!response.ok) throw new ApiError(response.status, await errorMessage(response));

  // 204 는 본문이 없다. json() 을 부르면 파싱에서 터진다.
  return response.status === 204 ? (undefined as T) : ((await response.json()) as T);
}

async function errorMessage(response: Response): Promise<string> { /* 그대로 */ }
```

```ts
export const REFRESH_TOKEN_COOKIE = "refresh_token";
/** 로그인 응답의 account({ accountId, email, realName, status }) JSON. */
export const ACCOUNT_COOKIE = "account";
/** 로그인의 deviceIdentifier. 같은 기기로 다시 로그인하면 그 기기의 이전 접속만 끊긴다. 로그아웃해도 남긴다. */

  httpOnly: true, // 브라우저 JS 가 토큰을 읽지 못하게 한다
  sameSite: "lax" as const,
  secure: process.env.NODE_ENV === "production",
  path: "/",
};
```

- [ ] **Step 6: `src/lib/session.ts`**

```ts
import { cookies } from "next/headers";
import { redirect } from "next/navigation";
import { ApiError, request, type RequestOptions, type Schemas } from "./api";
import {
  ACCESS_TOKEN_COOKIE, ACCOUNT_COOKIE, DEVICE_ID_COOKIE, REFRESH_TOKEN_COOKIE,
  accessTokenCookie, clearSessionCookies, deviceIdCookie, untilCookie,
} from "./session-cookies";

export type Account = Schemas["LoginAccountResponseDto"];
export interface Session { accessToken: string; account: Account }

/** 접속이 끝났을 때 가는 곳. 쿠키는 proxy 가 이 경로에서 지운다(서버 컴포넌트는 쿠키를 지울 수 없다). */
export const EXPIRED_LOGIN_PATH = "/login?expired=1";

/** 로그인에 성공하면 서버 액션에서 부른다. */
export async function saveLogin(result: Schemas["LoginResponseDto"]): Promise<void> {
  const jar = await cookies();
  const until = untilCookie(new Date(result.refreshTokenExpiresAt));
  jar.set(ACCESS_TOKEN_COOKIE, result.accessToken, accessTokenCookie());
  jar.set(REFRESH_TOKEN_COOKIE, result.refreshToken, until);
  jar.set(ACCOUNT_COOKIE, JSON.stringify(result.account), until);
}

export async function getSession(): Promise<Session | null> {
  const jar = await cookies();
  const accessToken = jar.get(ACCESS_TOKEN_COOKIE)?.value;
  const raw = jar.get(ACCOUNT_COOKIE)?.value;
  if (!accessToken || !raw) return null;
  try {
    return { accessToken, account: JSON.parse(raw) as Account };
  } catch {
    return null; // 손상된 쿠키는 로그아웃으로 취급한다
  }
}

/** 로그인이 필요한 화면 · 액션의 첫 줄. proxy 가 먼저 막지만 proxy 만 믿지 않는다. */
export async function requireSession(): Promise<Session> {
  const session = await getSession();
  if (!session) redirect("/login");
  return session;
}

/** 서버 액션 · 라우트 핸들러에서만 부른다. device_id 는 남긴다. */
export async function clearSession(): Promise<void> {
  clearSessionCookies(await cookies());
}

/** 서버 액션에서만 부른다(없으면 만들어 굽는다). */
export async function getDeviceId(): Promise<string> {
  const jar = await cookies();
  const existing = jar.get(DEVICE_ID_COOKIE)?.value;
  if (existing) return existing;
  const created = crypto.randomUUID();
  jar.set(DEVICE_ID_COOKIE, created, deviceIdCookie());
  return created;
}

/**
 * 로그인한 직원으로 부르는 API. 401 이면 접속이 끝난 것이다 — 다른 기기에서 비밀번호를 바꿨거나
 * 관리자가 접속을 끊으면 액세스 토큰이 남은 시간과 상관없이 바로 401 이 된다.
 */
export async function authedRequest<T>(path: string, options: Omit<RequestOptions, "accessToken"> = {}): Promise<T> {
  const { accessToken } = await requireSession();
  try {
    return await request<T>(path, { ...options, accessToken });
  } catch (error) {
    if (error instanceof ApiError && error.status === 401) redirect(EXPIRED_LOGIN_PATH);
    throw error;
  }
}
```

```ts
import { request, type Schemas } from "./api";

export type EnumValue = Schemas["EnumValueDto"];

// enum 은 api 배포 때만 바뀐다. 한 시간씩 서버에 캐시하고, 배포 뒤 늦어도 한 시간이면 새 값을 본다.
// (응답의 version 을 비교해 바로 버리는 일은 enum 을 자주 쓰게 되면 더한다.)
const ENUM_REVALIDATE_SECONDS = 60 * 60;

export async function getEnum(name: string): Promise<EnumValue[]> {
  const { enums } = await request<Schemas["EnumCatalogResponseDto"]>(`/enums/${encodeURIComponent(name)}`, {
    revalidate: ENUM_REVALIDATE_SECONDS,
  });
  return [...(enums[name] ?? [])].sort((a, b) => a.order - b.order);
}

/** 목록에 없는 값은 값 그대로 보인다(api 가 새 값을 더했는데 캐시가 아직 옛것일 때). */
export function labelOf(values: EnumValue[], value: string): string {
  return values.find((v) => v.value === value)?.label ?? value;
}
```

```ts
"use server";

import { redirect } from "next/navigation";
import { ApiError } from "@/lib/api";
import { login } from "@/lib/auth";
import { getDeviceId, saveLogin } from "@/lib/session";
import { CONNECTION_FAILED_MESSAGE } from "../_components/auth-screen";

export interface LoginState {
  email: string;
  error?: string;
  /** 5번 틀려 5분 잠김. 요청 제한(429)과 메시지로 가른다. */
  locked?: boolean;
}

// api 의 잠금 메시지 앞부분(account-auth.service.ts LOCKED_MESSAGE). 요청 제한 429 는 Nest 기본 메시지다.
const LOCKED_MESSAGE_PREFIX = "로그인이 잠겼습니다";

export async function loginAction(_previous: LoginState, formData: FormData): Promise<LoginState> {
  const email = String(formData.get("email") ?? "").trim();
  const password = String(formData.get("password") ?? "");
  if (!email || !password) return { email, error: "이메일과 비밀번호를 넣어 주세요" };

  try {
    const result = await login({ email, password, deviceIdentifier: await getDeviceId() });
    await saveLogin(result);
  } catch (error) {
    if (error instanceof ApiError) {
      if (error.status === 429 && error.message.startsWith(LOCKED_MESSAGE_PREFIX)) return { email, locked: true };
      if (error.status === 429) return { email, error: "시도가 많아 잠시 막았습니다. 잠시 뒤에 다시 시도해 주세요" };
      // 401 「이메일 또는 비밀번호가 올바르지 않습니다」 — 틀림 · 없는 계정 · 탈퇴 모두 같다.
      return { email, error: error.message };
    }
    if (error instanceof TypeError) return { email, error: CONNECTION_FAILED_MESSAGE };
    throw error;
  }
  redirect("/home");
}
```

```ts
import { NextResponse, type NextRequest } from "next/server";
import { ApiError } from "@/lib/api";
import { refreshAccessToken } from "@/lib/auth";
import {
  ACCESS_TOKEN_COOKIE, ACCOUNT_COOKIE, REFRESH_TOKEN_COOKIE,
  accessTokenCookie, clearSessionCookies, untilCookie,
} from "@/lib/session-cookies";

// 로그인 없이 여는 화면.
const PUBLIC_PATHS = ["/login", "/password-reset"];

const isPublic = (pathname: string) => PUBLIC_PATHS.some((path) => pathname === path || pathname.startsWith(`${path}/`));

/**
 * 접속 유지(WHALEERP-166). 액세스 토큰(15분)이 없고 갱신 토큰이 있으면 다시 받아 굽는다.
 * 같은 요청을 처리할 서버 컴포넌트도 새 토큰을 보도록 요청 쿠키에도 넣는다.
 * 갱신이 401 이면 접속이 끝난 것이라 쿠키를 지우고 만료 안내로 보낸다.
 */
export async function proxy(request: NextRequest) {
  const { pathname, searchParams } = request.nextUrl;

  // 서버 컴포넌트는 쿠키를 지울 수 없어 401 을 받으면 여기로 보낸다. 남은 쿠키를 지워야 /home ↔ /login 을 돌지 않는다.
  if (pathname === "/login" && searchParams.has("expired")) {
    const response = NextResponse.next();
    clearSessionCookies(response.cookies);
    return response;
  }

  let accessToken = request.cookies.get(ACCESS_TOKEN_COOKIE)?.value;
  const refreshToken = request.cookies.get(REFRESH_TOKEN_COOKIE)?.value;
  const account = request.cookies.get(ACCOUNT_COOKIE)?.value;
  let refreshedUntil: Date | null = null;

  if (!accessToken && refreshToken && account) {
    try {
      const refreshed = await refreshAccessToken(refreshToken);
      accessToken = refreshed.accessToken;
      refreshedUntil = new Date(refreshed.refreshTokenExpiresAt);
      request.cookies.set(ACCESS_TOKEN_COOKIE, accessToken);
    } catch (error) {
      if (error instanceof ApiError && error.status === 401) {
        const response = NextResponse.redirect(new URL("/login?expired=1", request.url));
        clearSessionCookies(response.cookies);
        return response;
      }
      // api 미기동 · 429 등은 접속이 끝난 게 아니다. 쿠키를 그대로 두고 로그인 화면으로만 보낸다.
      if (!(error instanceof ApiError) && !(error instanceof TypeError)) throw error;
    }
  }

  const loggedIn = Boolean(accessToken && account);
  let response: NextResponse;
  if (!loggedIn && !isPublic(pathname)) response = NextResponse.redirect(new URL("/login", request.url));
  else if (loggedIn && pathname === "/login") response = NextResponse.redirect(new URL("/home", request.url));
  else response = NextResponse.next({ request: { headers: request.headers } });

  if (accessToken && refreshedUntil && refreshToken && account) {
    response.cookies.set(ACCESS_TOKEN_COOKIE, accessToken, accessTokenCookie());
    // 갱신 토큰은 회전하지 않는다. 값은 그대로, 만료만 api 가 준 새 시각으로 민다.
    response.cookies.set(REFRESH_TOKEN_COOKIE, refreshToken, untilCookie(refreshedUntil));
    response.cookies.set(ACCOUNT_COOKIE, account, untilCookie(refreshedUntil));
  }
  return response;
}

export const config = {
  // 정적 파일 · 디자인 견본 · 데모는 뺀다(점이 든 경로 = public 파일).
  matcher: ["/((?!_next/|design|demo|.*\\..*).*)"],
};
```

`request.cookies.set` 은 요청의 `cookie` 헤더를 고친다. 그 헤더를 `NextResponse.next({ request: { headers } })` 로 넘겨야 서버 컴포넌트의 `cookies()` 가 새 토큰을 본다. 확인: Step 6.

```ts
import { cookies } from "next/headers";

// 비밀번호 재설정 단계(핀 요청 → 핀 입력 → 새 비밀번호) 사이에 들고 다니는 값.
// 핀은 새 비밀번호 요청에 다시 보내야 하지만 URL · 로그에 남기면 안 되므로 httpOnly 쿠키에 둔다.

const PASSWORD_RESET_COOKIE = "password_reset";
/** 핀 입력과 새 비밀번호를 합쳐 핀을 낸 시각부터 10분(api 한 시계). */
export const PIN_VALID_MS = 10 * 60 * 1000;
/** api 는 직전 발급 뒤 1분 안의 요청을 보내지 않고도 204 로 답한다. 그동안 「다시 받기」를 막는다. */
export const PIN_RESEND_MS = 60 * 1000;
/** 쿠키는 10분보다 길게 둔다. 10분이 지난 뒤 들어와도 「시간이 지났습니다」를 보여 주려는 것이다. */
const COOKIE_SECONDS = 30 * 60;

export interface PasswordReset {
  email: string;
  /** 핀을 요청한 시각(ms). 서버가 실제로 낸 시각과 몇 초 다를 수 있어 시계는 안내용이다 — 판정은 api 가 한다. */
  issuedAt: number;
  /** 확인을 마친 핀. 있으면 새 비밀번호 단계다. */
  pin?: string;
}

export async function readPasswordReset(): Promise<PasswordReset | null> {
  const raw = (await cookies()).get(PASSWORD_RESET_COOKIE)?.value;
  if (!raw) return null;
  try {
    return JSON.parse(raw) as PasswordReset;
  } catch {
    return null;
  }
}

/** 서버 액션에서만 부른다. */
export async function savePasswordReset(state: PasswordReset): Promise<void> {
  (await cookies()).set(PASSWORD_RESET_COOKIE, JSON.stringify(state), {
    httpOnly: true,
    sameSite: "lax",
    secure: process.env.NODE_ENV === "production",
    path: "/password-reset", // 재설정 화면 밖으로는 보내지 않는다
    maxAge: COOKIE_SECONDS,
  });
}

/** 서버 액션에서만 부른다. */
export async function clearPasswordReset(): Promise<void> {
  (await cookies()).delete({ name: PASSWORD_RESET_COOKIE, path: "/password-reset" });
}

export const isPinExpired = (state: PasswordReset, now = Date.now()) => now - state.issuedAt >= PIN_VALID_MS;

/** 화면에 보일 이메일: @ 앞을 절반만(최대 5자) 남긴다. haeun.lee@gmail.com → haeun****@gmail.com */
export function maskEmail(email: string): string {
  const at = email.indexOf("@");
  if (at <= 0) return email;
  const local = email.slice(0, at);
  return `${local.slice(0, Math.min(5, Math.ceil(local.length / 2)))}****${email.slice(at)}`;
}
```

```ts
"use server";

import { redirect } from "next/navigation";
import { ApiError } from "@/lib/api";
import { requestPasswordResetPin } from "@/lib/auth";
import { PIN_RESEND_MS, readPasswordReset, savePasswordReset } from "@/lib/password-reset";
import { CONNECTION_FAILED_MESSAGE } from "../_components/auth-screen";

export interface RequestPinState { email: string; error?: string }

/** api 오류를 폼 문구로. 503(발송기 없음) · 400(형식)은 api 메시지를 그대로 쓴다. */
function messageOf(error: unknown): string {
  if (error instanceof ApiError) return error.message;
  if (error instanceof TypeError) return CONNECTION_FAILED_MESSAGE;
  throw error;
}

export async function requestPinAction(_previous: RequestPinState, formData: FormData): Promise<RequestPinState> {
  const email = String(formData.get("email") ?? "").trim();
  if (!email) return { email, error: "이메일을 넣어 주세요" };
  try {
    await requestPasswordResetPin(email);
  } catch (error) {
    return { email, error: messageOf(error) };
  }
  await savePasswordReset({ email, issuedAt: Date.now() });
  redirect("/password-reset/pin");
}

export interface ResendState { notice?: string; error?: string }

// useActionState 로 부르므로 (이전 상태, 폼) 을 받는다. 둘 다 쓰지 않는다.
export async function resendPinAction(_previous: ResendState, _formData: FormData): Promise<ResendState> {
  const state = await readPasswordReset();
  if (!state) redirect("/password-reset");
  // 1분 안이면 api 가 보내지 않고 204 를 준다. 보냈다고 말하지 않도록 여기서 먼저 막는다(화면도 버튼을 막는다).
  if (Date.now() - state.issuedAt < PIN_RESEND_MS) return { error: "1분 뒤에 다시 받을 수 있습니다" };
  try {
    await requestPasswordResetPin(state.email);
  } catch (error) {
    return { error: messageOf(error) };
  }
  await savePasswordReset({ email: state.email, issuedAt: Date.now() });
  return { notice: "새 인증번호를 보냈습니다. 앞서 받은 인증번호는 쓸 수 없습니다" };
}
```

```tsx
"use client";

import { useEffect, useState } from "react";

/** 1초마다 지금 시각. 처음 그릴 때는 서버와 같게 null 이다(하이드레이션 불일치 방지). */
export function useNow(): number | null {
  const [now, setNow] = useState<number | null>(null);
  useEffect(() => {
    setNow(Date.now());
    const timer = setInterval(() => setNow(Date.now()), 1000);
    return () => clearInterval(timer);
  }, []);
  return now;
}

/** 핀 입력 · 새 비밀번호가 함께 쓰는 남은 시간(한 시계). 안내용이고 판정은 api 가 한다. */
export function Countdown({ deadline }: { deadline: number }) {
  const now = useNow();
  const left = now === null ? null : Math.max(0, deadline - now);
  const text = left === null ? "--:--" : `${String(Math.floor(left / 60_000)).padStart(2, "0")}:${String(Math.floor((left % 60_000) / 1000)).padStart(2, "0")}`;
  return (
    <span>
      남은 시간 <b className="text-staff-text tabular-nums">{text}</b>
    </span>
  );
}
```

```ts
// 비밀번호 규칙 안내(WHALEERP-192). 화면에 맞음 · 아직을 보이는 데만 쓰고, 통과 여부는 api 가 정한다(400 + 사유).
// 대문자 · 소문자 · 숫자 · 특수문자 중 3종 이상이면 8자↑, 2종이면 10자↑, 1종 불가, 20자 이하, 이메일이나 @ 앞과 같으면 불가.

export interface PasswordRuleCheck { kinds: boolean; length: boolean; notEmail: boolean }

export function checkPasswordRules(password: string, email: string): PasswordRuleCheck {
  const kinds = [/[A-Z]/, /[a-z]/, /[0-9]/, /[^A-Za-z0-9]/].filter((pattern) => pattern.test(password)).length;
  const minimum = kinds >= 3 ? 8 : 10;
  const lower = password.toLowerCase();
  const address = email.toLowerCase();
  return {
    kinds: kinds >= 2,
    length: password.length >= minimum && password.length <= 20,
    notEmail: password.length > 0 && lower !== address && lower !== address.split("@")[0],
  };
}
```

```ts
import { resetPassword } from "@/lib/auth";
import { clearPasswordReset } from "@/lib/password-reset";
import { clearSession } from "@/lib/session";

export interface NewPasswordState { error?: string; timedOut?: boolean }

export async function resetPasswordAction(_previous: NewPasswordState, formData: FormData): Promise<NewPasswordState> {
  const newPassword = String(formData.get("newPassword") ?? "");
  const confirmation = String(formData.get("newPasswordConfirmation") ?? "");
  const state = await readPasswordReset();
  if (!state?.pin) redirect("/password-reset");
  if (newPassword !== confirmation) return { error: "두 칸의 비밀번호가 다릅니다" };
  try {
    await resetPassword({ email: state.email, pin: state.pin, newPassword });
  } catch (error) {
    // 400: 규칙 위반. 핀은 그대로라 이 자리에서 다시 입력한다. 사유는 api 메시지.
    if (error instanceof ApiError && error.status === 400) return { error: error.message };
    // 401: 10분이 지났거나 핀이 닫혔다. 앞서 받은 핀은 다시 쓸 수 없다.
    if (error instanceof ApiError && error.status === 401) {
      await clearPasswordReset();
      return { timedOut: true };
    }
    return { error: messageOf(error) };
  }
  // 모든 기기의 접속이 끊겼다. 이 기기의 쿠키도 지운다.
  await clearPasswordReset();
  await clearSession();
  redirect("/login?reset=1");
}
```
