# 진입·가입 화면 가이드 (초대 코드 → 계정 등록)

- 목적: 진입·가입 목업과 데모를 2026-10-19 운영 정책에 맞추고, 김민식 님이 구현할 때 볼 화면 기준을 남긴다.
- 이번에 고치는 것: `docs/mockup/app/join.html`, `docs/demo/src/pages/join/index.mjs`(+ `node docs/demo/build.mjs` 결과)뿐이다. 앱 코드와 api 는 고치지 않는다.
- Plane: #141 초대 링크 진입과 토큰 확인, #142 계정 등록과 인적사항 입력, #144 소속 추가 확인과 복귀 확인 (모두 김민식). #143 본인인증과 연결 결과 안내는 정책에서 없어졌다.

## 결정 (2026-10-19 재영)

- **가입 첫 단계는 「초대 코드」 입력이다.** 초대 토큰(43자)은 사람이 칠 수 없다. 그래서 짧은 초대 코드를 따로 두고, 직원이 앱을 직접 열어도 이 코드로 가입을 시작한다. 초대 링크를 열면 코드 입력을 건너뛴다.
- **초대 링크의 토큰은 `#token=` 에 싣는다** — `/invite#token=…`. 재설정 링크(`/password-reset/link#token=`)와 같은 방식이다. 서버 접근 기록에 토큰이 남지 않는다. 지금 api 는 `/invite/{토큰}` 으로 만든다(`contract-send.service.ts`). 고쳐야 한다.

## 화면 순서

```
링크로 열기  /invite#token=…  ─────────────┐
앱 직접 열기  로그인 → 「초대 코드로 가입」 → ① 초대 코드 입력 ─┤
                                            ▼
                                   ② 초대 확인 ─(이미 계정 있음)→ 소속 추가 확인 / 복귀 확인
                                            ▼
                                   ③ 계정 등록 ─(만 19세 미만)→ 가입 불가
                                            ▼
                                   ④ 가입 완료 → 날인 요청 팝업(전자계약) / 신고 정보(종이 계약)
예외: 만료·무효 초대, 이미 가입을 마친 초대(→ 로그인), 코드 입력 잠금
```

본인인증 단계(verify)와 연결 보류(held)는 없다. 가입하면 계정은 초대의 직원 레코드에 바로 이어진다(운영 정책 JOI-04·05, ACC-23).

## 화면별 기준

### ① 초대 코드 입력 — `/join` (새 화면)
- 진입: 로그인 화면 아래 「초대 코드로 가입」. 비로그인 공개 경로에 `/join` · `/invite` 를 더한다(지금 `PUBLIC_PATHS` 는 login · password-reset · email-find 뿐).
- 입력 칸
  - 휴대전화번호: 초대를 받은 번호다. 숫자만 받고 하이픈은 화면에서 넣는다.
  - 초대 코드: 8자리.
- 버튼은 「다음」 하나다. 두 칸이 다 차야 켜진다.
- 맞지 않으면 「휴대전화번호나 초대 코드를 다시 확인해 주세요」만 보인다. 어느 쪽이 틀렸는지, 그 번호로 초대가 있는지는 알리지 않는다.
- 같은 휴대전화번호로 5회 틀리면 30분 잠근다. 접속 IP 기준 제한도 따로 둔다(JOIN-7). 잠기면 남은 시간과 「30분 뒤 다시 시도하거나, 근무지 관리자에게 재발송을 요청해 주세요」를 보인다.
- 아래 도움말: 「초대 코드는 근무지에서 보낸 알림톡·문자에 있습니다. 받지 못했으면 근무지에 다시 보내 달라고 요청해 주세요.」

### ② 초대 확인 — `/invite#token=…` 또는 ①에서
- 보이는 것: 초대한 근무지 이름, 고용 형태, 「초대는 받은 날부터 30일 동안 쓸 수 있습니다」, 버튼 「가입 시작」.
- 기존 계정 정보와 직원 레코드 값(이름·생년월일 등)은 보이지 않는다.
- 갈래
  - 그 번호의 계정이 이미 있다 → 「이미 계정이 있습니다」와 로그인 버튼(목업 has-account). 로그인한 뒤 앱 안에서 소속 추가 확인 / 복귀 확인이 뜬다(운영 정책 JOI-02). 확인 화면은 지금 목업의 addsite 를 그대로 쓴다.
  - 이미 가입을 마친 초대다 → 「이미 가입을 마친 초대입니다」와 로그인 버튼.
  - 만료됐거나 재초대로 바뀐 초대다 → 만료 안내와 「근무지에 다시 초대해 달라고 요청해 주세요」. 링크와 코드가 똑같이 무효가 된다.

### ③ 계정 등록 — `/join/signup`
- 단계 막대: 코드로 오면 「3 / 4」, 링크로 오면 코드 입력이 없어 「2 / 3」이다(목업 signup · signup-link).
- 인적사항(운영 정책 ACC-23): 이름, 휴대전화번호, 생년월일 8자리, 성별(남·여), 외국인 여부.
  - 휴대전화번호는 **읽기 전용**이다(JOIN-7). 코드로 왔으면 코드와 함께 확인된 번호, 링크로 왔으면 그 초대(근로계약서)의 번호를 채운다. 번호가 틀리면 관리자가 날인 전에 당사자 정보를 고쳐 다시 초대한다(운영 정책 CTR-28). 계정 번호는 매칭 키라, 고칠 수 있으면 남의 번호로 가입해 그 사람의 다음 초대를 막을 수 있다.
  - 생년월일은 가입한 뒤 고칠 수 없다고 칸 아래에 적는다(ACC-13).
- 로그인 정보
  - 이메일(아이디).
  - 비밀번호·비밀번호 확인: 3종 섞으면 8자, 2종이면 10자 이상, 20자까지. 이메일 앞부분과 같으면 받지 않는다(ACC-12).
- 주소: 검색으로 고르고 상세주소만 직접 넣는다(ACC-20).
- 약관 동의: 필수 「직원 앱 서비스 이용약관」·「개인정보 수집·이용」, 선택 「마케팅 정보 수신」. 가맹 점포면 「본사 제공 동의(선택)」를 더한다(운영 정책 ATT-30). 위치정보 동의는 여기서 받지 않는다(첫 출근 때, ATT-06).
- 버튼 「가입하기」.

### 가입 불가 (만 19세 미만)
- 가입 시점에 만 19세 미만이면 계정을 만들지 않는다. 운영 정책 ACC-22 의 안내문을 보인다. 뒤로 가서 다시 시도하는 길은 두지 않는다.

### ④ 가입 완료
- 「가입을 마쳤습니다」와 근무지 이름을 보인다. 로그인된 상태로 홈에 간다.
  - 전자계약: 홈 위에 날인 요청 팝업(HOME-1). 계약서는 가입과 함께 자동으로 발송된다(JOI-09).
  - 종이 계약: 날인 없이 신고 정보 입력으로 간다(CON-8).

## 구현 때 api 에 필요한 것 (김민식 님 확인용)

| 할 일 | 메모 |
|---|---|
| 초대 코드 발급 | 초대(`invitations`)마다 8자리 코드. 토큰처럼 해시로 저장한다. 재초대하면 앞 코드도 무효가 된다 |
| 알림톡 · SMS 본문에 코드 싣기 | `TALK_STAFF_INVITATION` 본문과 변수를 바꾼다. 카카오 검수 문구도 다시 받아야 한다 |
| 링크를 `#token=` 으로 | `contract-send.service.ts` 의 링크 생성 |
| 초대 확인 | 토큰 또는 (휴대전화번호 + 코드)로 초대를 찾는다. 로그인 없이 부르고 횟수를 제한한다 |
| 가입 | 계정 생성 · 직원 레코드 연결 · 초대 수락 · 약관 동의 기록 · 계약서 자동 발송 · 세션 발급을 한 트랜잭션으로 한다. 만 19세 미만이면 가입 불가 · 운영 알림 |
| `accounts` 칸 | 성별 · 외국인 여부 칸이 없다 |
| 직원 약관 동의 기록 | `terms_agreement_logs` 는 관리자 계정 전용(1팀)이라 직원 동의를 남길 자리가 없다 |
| 알림톡 버튼 | 지금 링크는 SMS 대체 때만 간다. 알림톡이 성공하면 직원이 링크를 받지 못한다 |

## 쟁점

- JOIN-1 변경: 「토큰 + 번호 이중 일치」 → 가입하면 초대의 직원 레코드에 잇는다(JOI-04, 10-19).
- JOIN-4 확정 정리: 인적사항은 계정 등록 화면에서 받는다(ACC-23). 본인인증이 없어 「전/후」 질문이 사라졌다.
- **JOIN-7 확정 (2026-10-19 재영)**: 초대 코드로 가입을 시작한다.
  - 코드 모양: 8자리 대문자 + 숫자. 헷갈리는 0 · O · 1 · I 는 뺀다.
  - 휴대전화번호와 함께 받는다. 둘이 모두 맞아야 열린다.
  - 잠금: 같은 번호로 5회 틀리면 30분 잠근다. 접속 IP 기준 제한을 더한다. 잠기면 30분 뒤 다시 시도하거나 근무지 관리자에게 재발송을 요청한다(IP 제한에 걸리면 재발송을 받아도 바로 풀리지 않는다).
  - 관리자 웹에는 코드를 보이지 않는다(해시 저장). 필요하면 재발송한다.
  - api: 서버는 가입 요청의 휴대전화번호를 받지 않고 초대 · 코드 확인 결과에서 가져온다. 화면의 읽기 전용만으로는 막히지 않는다.
  - api: 초대가 없는 번호도 같은 기준으로 실패 횟수를 센다. 잠금 여부로 초대가 있는지 드러나지 않게 한다.
  - 계정 등록 화면의 휴대전화번호는 읽기 전용으로 고정한다(위 ③).
  - 운영 정책 JOI-02 · 03, 용어집(초대 코드), Manyfast 는 기획 세션이 고친다. api 일감은 기획 세션이 Plane 에 새로 올린다.
