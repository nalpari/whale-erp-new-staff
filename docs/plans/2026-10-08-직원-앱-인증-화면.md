# 직원 앱 인증 화면 (2026-10-08)

## 왜

whale-erp-api 에 직원 근무 앱(3팀 `accounts`) 인증 API 가 들어왔다(api PR #7). 직원 앱의 첫 실제 화면으로
이 API 를 부르는 로그인 · 접속 유지 · 로그아웃 · 비밀번호 재설정(핀)을 만든다. 홈 API 는 아직 없으므로
로그인 뒤 갈 곳은 임시 홈을 두고, 실제 홈은 다른 사람이 채운다.

## 범위

| 만든다 | API |
|---|---|
| 로그인 (틀림 · 5분 잠금 · 요청 제한) | `POST /auth/account/login` |
| 접속 유지 · 만료 시 로그인으로 복귀 | `POST /auth/account/refresh` |
| 로그아웃 (확인 시트) | `POST /auth/account/logout` |
| 비밀번호 재설정 ① 핀 요청 ② 핀 입력 ③ 새 비밀번호 | `password-reset-pins` · `password-reset-pins/verify` · `password-reset` |
| 임시 홈 (이름 · 계정 상태 · 로그아웃) | 로그인 응답 + `GET /enums/AccountStatus` |

만들지 않는다: 이메일 찾기 · 관리자 초기화 링크(API 없음), 퇴직(관리자 웹 몫), 실제 홈.

> 바뀜(2026-10-13): api #28 머지로 관리자 초기화 링크 API 가 생겼다(201 `{ issuedAt, expiresAt }`, 토큰은 링크 fragment `#token=`). `/password-reset/link` 화면은 별도 일감(Plane #173)이다.

`src/app/demo/` 는 **건드리지 않는다**. 기획 확인용으로 계속 고쳐지므로, 실제 화면은 데모의 마크업 · 문구를
참고해 새로 쓴다. `_components` 조각도 옮기지 않고 필요한 것을 공통 부품으로 새로 만든다.

## 라우트

| 경로 | 동작 |
|---|---|
| `/` | 세션이 있으면 `/home`, 없으면 `/login` |
| `/login` | 401 은 서버 메시지를 그대로. 429 는 메시지에 「잠겼」가 있으면 잠금 안내 + 「비밀번호 다시 정하기」, 아니면 요청 제한 안내. `?expired=1` 접속 만료 안내, `?reset=1` 비밀번호를 바꿨다는 안내 |
| `/password-reset` | 이메일 → 핀 요청. 204 면 `/password-reset/pin`, 503 이면 「잠시 뒤 다시」. 계정이 없어도 204 라 「메일을 보냈다」로만 안내 |
| `/password-reset/pin` | 핀 입력. 발급 시각부터 10분 남은 시간 표시 · 「다시 받기」. 401 은 「올바르지 않거나 만료」 하나로(틀림 · 만료 · 5회 닫힘을 API 가 가르지 않는다). 204 면 다음 단계 |
| `/password-reset/new-password` | 400 은 사유를 보이고 그 자리에서 다시 입력. 401 은 「시간이 지났습니다」 + 핀 다시 받기. 204 면 재설정 쿠키 · 세션을 지우고 `/login?reset=1` |
| `/home` | 임시. 이름 · 계정 상태(`LINK_HOLD` 면 관리자 확인 중 안내, 한글은 `getEnum`) · 로그아웃 시트. 맨 위 주석에 다른 작업자가 채울 자리임을 적는다 |

폴더는 라우트 그룹 `(auth)`(로그인 · 재설정)와 `(app)`(로그인 필요)으로 나눈다. `/design` · `/demo` 는 그대로다.

## 세션 · 접속 유지

- 쿠키(모두 httpOnly, `sameSite: lax`, 운영에서 `secure`)
  - `access_token` — 15분
  - `refresh_token` — 응답의 `refreshTokenExpiresAt` 까지. 갱신해도 회전하지 않으므로 값은 그대로 두고 만료만 민다
  - `account` — `{ accountId, email, realName, status }` JSON
  - `device_id` — 첫 로그인 때 UUID 를 만들어 1년. 로그인의 `deviceIdentifier` 로 보낸다
- `src/proxy.ts` (Next 16 의 미들웨어, Node 런타임)
  - 정적 파일 · `/design` · `/demo` 는 matcher 에서 뺀다.
  - `access_token` 이 없고 `refresh_token` 이 있으면 refresh 를 부른다. 성공하면 새 값을 응답 쿠키에 굽고,
    같은 요청의 서버 컴포넌트가 보도록 요청 쿠키에도 넣는다. 401 이면 쿠키를 지우고 `/login?expired=1`.
  - 세션 없이 `(app)` 경로면 `/login`, 세션이 있는데 `/login` 이면 `/home`.
- proxy 만 믿지 않는다. `(app)` 의 서버 컴포넌트 · 서버 액션은 `requireSession()` 을 거치고, 인증 API 호출이
  401 이면(다른 기기에서 비밀번호를 바꿔 토큰이 즉시 무효가 된 경우 등) `/login?expired=1` 로 보낸다.
- 로그아웃: Bearer 로 `POST /auth/account/logout`. 401 이어도 쿠키를 지우고 `/login`.

## 재설정 단계 사이의 상태

httpOnly 쿠키 `password_reset` 하나에 `{ email, issuedAt, pin? }` 을 담고 10분 뒤 만료한다. 핀은 새 비밀번호
요청에 다시 보내야 하므로 서버 쪽에 들고 있되 URL · 로그에 넣지 않는다. 각 단계 화면은 쿠키가 없거나 필요한
값이 없으면 `/password-reset` 으로 되돌린다. 「다시 받기」는 `issuedAt` 을 새로 쓰고 `pin` 을 지운다.

## 기반 코드

| 파일 | 내용 |
|---|---|
| `package.json` | devDependency `openapi-typescript`, 스크립트 `openapi:types` — `${WHALE_API_DIR:-../whale-erp-api}/openapi/openapi.json` → `src/lib/api-types.d.ts`(커밋) |
| `src/lib/api.ts` | `request()` · `ApiError` · `baseUrl()` 는 남긴다. 견본 `AuthUser` · `Session` · 쿠키 함수는 `session.ts` 로 옮기며 새 모양으로 바꾼다. 요청 · 응답 타입은 `api-types.d.ts` 에서 |
| `src/lib/session.ts` | 쿠키 읽기 · 쓰기 · 지우기, `requireSession()` |
| `src/lib/auth.ts` | `login` · `refreshAccessToken` · `logout` · `requestPasswordResetPin` · `verifyPasswordResetPin` · `resetPassword` (동사 + 자원) |
| `src/lib/enums.ts` | `getEnum(name)` · `labelOf(values, value)`. 응답을 Next 서버 캐시로 오래 둔다 |

서버 액션의 오류는 CLAUDE.md 규칙대로 한다: `ApiError` → 폼 상태, `TypeError`(api 미기동) → 연결 실패 문구,
그 밖은 다시 던진다. `redirect()` 는 try 밖에서 부른다.

## 화면 부품

있는 공통 부품(`Button` · `TextField` · `Notice` · `BottomSheet` · `BrandLogo` · `Card` · `StaffRoot` 등)을 먼저 쓴다.
데모에만 있는 모양 중 이번 화면에 필요한 것 — `Dock` · `Alert` · `DangerButton` — 은
데모를 참고해 `src/components/common` 에 새로 만들고 DESIGN.md Components 에 적는다. 데모 쪽 조각은 그대로 둔다.
데모의 화면 전환 슬라이드는 화면 이동 링크에 `transitionTypes` 를 붙이는 방식(DESIGN.md Motion)으로 쓴다.

## 데모 정적 빌드

`DEMO_EXPORT=1` 은 `output: "export"` 라 proxy · 서버 액션 · 쿠키를 쓰는 라우트가 있으면 빌드가 깨진다.
`scripts/build-demo.mjs` 가 빌드 동안 `src/app/(app)` · `src/app/(auth)` · `src/proxy.ts` 를
잠시 옆으로 치우고 `finally` 에서 되돌린다.

## 검증

테스트 러너가 없다. `pnpm lint` · `pnpm build` · `node scripts/build-demo.mjs`(산출물 `docs/demo` 는 커밋하지 않고
되돌림) 가 통과해야 한다. 로컬 api 를 띄울 수 있으면 로그인 → 홈 → 로그아웃, 액세스 토큰 쿠키를 지운 뒤 자동 갱신,
갱신 토큰을 지운 뒤 만료 복귀, 틀린 비밀번호 · 틀린 핀 401 을 손으로 돌린다. 핀은 api 의 Noop 발송기라 실제로
받을 수 없어 재설정 성공 경로는 확인하지 못한다.
