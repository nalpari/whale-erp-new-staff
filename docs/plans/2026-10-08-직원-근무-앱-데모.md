# 직원 근무 앱 데모 (2026-10-08)

## 왜

관리자 웹 데모(front `docs/demo`)처럼, 직원 근무 앱도 눌러 보는 클릭 데모를 만든다(2026-10-08 재영 승인, 기획 세션 요청).
목업(`docs/mockup/app`)은 결정을 받아내는 문서이고, 데모는 같은 내용을 실제 앱 부품으로 그려 본다.

## 원칙

- 디자인은 `DESIGN.md`, 부품은 `src/components/common` 을 그대로 쓴다. 새 부품은 DESIGN.md 규칙 안에서 만들고 DESIGN.md 에 적는다.
- 내용·상태·화면 문구는 목업 11장이 기준이다. 확정된 쟁점 상태를 빠짐없이 넣는다. 용어는 용어집.
- `/design`(Figma 화면 7개)은 고치지 않는다. 데모는 `/demo` 아래에 따로 만든다.
- 휴대전화 폭(최대 430px)으로 그리고, 버튼·탭·하단 메뉴로 실제로 옮겨 다닌다. 가짜 값만 쓰고 API 는 부르지 않는다.
- Figma 시안이 없는 화면은 머리 주석에 「Figma 없음 — DESIGN.md 기준 초안」을 적는다.

## 구조

| 경로 | 내용 |
|---|---|
| `src/app/demo/layout.tsx` | `StaffRoot` + 가운데 휴대전화 폭 기둥 |
| `src/app/demo/page.tsx` | 데모 입구. 장·화면 목록 |
| `src/app/demo/_components/` | 데모 전용 도구. `useDemoState`(화면 안 상태, 주소 `#상태` 와 맞춤) · `DemoStates`(화면 밖 상태 전환 도구) |
| `src/app/demo/<화면>/page.tsx` | 화면 하나 = 목업 한 장. 상태는 같은 화면 안에서 바꾼다 |

상태 전환 도구는 앱 디자인이 아니라 데모를 보는 도구라, `/design` 의 「가이드」 버튼처럼 짙은 남색으로 화면 밖(오른쪽 위)에 둔다.
다른 화면의 특정 상태로 가는 링크는 `/demo/login#locked` 처럼 주소 끝에 상태를 붙인다.

## 미니에 올리기

미니 8081 은 nginx 정적 서버라 Next 서버가 없다. 그래서 정적 내보내기를 커밋한다.

1. `node scripts/build-demo.mjs` — `DEMO_EXPORT=1 next build`(`output: "export"`, `trailingSlash`, 이미지 최적화 끔)로 `out/` 을 만들고 `docs/demo/` 로 옮긴다.
2. 미니 nginx 8081 블록에 `/demo/` · `/_next/` · `/icons/` 를 `docs/demo/` 아래로 잇는 alias 를 더한다(한 번만).
3. 장마다 커밋 → 푸시 → `pull-whale-erp staff`.

## 데모 공통 조각 정리 (2026-10-08)

화면을 병렬로 만들면서 같은 조각(아래 버튼 줄, 본문 틀, 안내 판, 이름·값 줄, 결과 도장, 토스트, 버튼형 뒤로 가기 머리줄, 경고 안내 판, 위험 확정 버튼, 체크칸 등)이 화면 파일마다 복사됐다.
두 화면 이상이 쓰는 것만 `src/app/demo/_components/` 로 옮기고 화면은 그것을 가져다 쓴다. 한 화면만 쓰는 조각은 그 화면에 둔다.

- 동작·문구·상태 목록은 바꾸지 않는다. 모양이 조금씩 다르면 가장 많이 쓰는 모양으로 맞추고, 눈에 띄게 달라지는 차이만 작은 prop 하나로 남긴다.
- 옮긴 조각은 DESIGN.md Components 끝 「데모 조각」 절에 한 줄씩 적는다. 공통 부품(`src/components/common`)과 `/design` 은 고치지 않는다.
- 확인: `pnpm lint` · `pnpm build`, dev 서버로 11개 화면 대표 상태 확인.
