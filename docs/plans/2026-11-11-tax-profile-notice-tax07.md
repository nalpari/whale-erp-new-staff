# 신고 정보 안내 문구를 운영 정책 TAX-07에 맞춘다

근거: 2026-11-11 재영 결정(기획 세션 header 전달). 지금 안내는 「관리자에게는 일부를 가린 형태로만 보이고」라서 급여 계좌도 가려지는 것처럼 읽힌다. 운영 정책 TAX-07에 따르면 관리자 화면에서 가려 보이는 것은 주민등록번호뿐이다. 급여 계좌는 급여 이체에 써야 해서 그 근무지 사업주 쪽 관리자에게 은행 이름과 계좌번호 전체로 보인다.

## 문안

「넣은 정보는 <strong>암호화해 보관</strong>합니다. 관리자에게 주민등록번호는 일부를 가린 형태로만 보이고, 급여 계좌는 급여를 이체하도록 그대로 보입니다. 신고 서류를 만들고 급여를 이체할 때만 씁니다.」

## 고칠 것

- 앱 처음 넣기 안내 `src/app/(app)/me/memberships/[staffMemberId]/tax-profile/new/new-tax-profile.tsx`: 위 문안으로 바꾼다.
- 앱 등록된 값 화면 `…/tax-profile/page.tsx`: 「관리자 화면에도 가려진 형태로만 보입니다」를 같은 뜻으로 고친다(지시의 5번, 같은 뜻의 추가 자리).
- 데모 `docs/demo/src/pages/tax/index.mjs`: 처음 넣기 안내는 위 문안으로 쓰되 데모의 「사용합니다」 말투에 맞춘다. 등록된 값 안내는 「관리자에게 주민등록번호는 일부를 가린 형태로만 보이고, 급여 계좌는 급여를 이체하도록 그대로 보입니다.」로 바꾼다. 수정한 뒤 `node docs/demo/build.mjs`로 `docs/demo/tax/index.html`을 다시 만든다.
- 목업 `docs/mockup/app/tax.html`: 처음 넣기 안내와 등록된 값 안내를 앱과 같은 뜻으로 고친다. 「관리자 웹에는 마스킹만 보낸다」고 적은 설계 메모 두 곳도 함께 고친다.

## 하지 않는 것

- 동작, api, 관리자 웹, 그 밖의 문구.
- 목업의 기획 명세 인용(「암호화 저장·마스킹 노출」)은 원문 인용이라 그대로 둔다.
- 데모 등록된 값 화면에서 직원 본인에게 계좌를 가려 보이는 표시는 관리자 노출과 다른 이야기라 그대로 둔다.

## 검증

- `grep` 으로 계좌까지 가린다고 읽히는 문구가 남지 않았는지 본다.
- 앱 lint · tsc.
- 데모 빌드 뒤 바뀐 산출물이 `docs/demo/tax/index.html` 뿐인지 본다.
