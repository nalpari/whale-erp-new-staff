PDF 내용 · 글꼴은 api 가 만든다) · PAY-4(만든 날부터 3년 — api 가 거른다) · PAY-7(3.3% 끝자리 안내)을 따르고 「입금」이라는 말은 쓰지 않는다 — 데모 안내 시트의 「급여 지급(입금)」도 괄호를 뺐다. 번호가 1..2147483647 밖이거나 api 가 404 면 404. 목록을 받지 못하면(api 오류 · 연결 실패) `error.tsx`.
* `src/proxy.ts` - 접속 유지. 액세스 토큰이 없고 갱신 토큰이 있으면 `/auth/account/refresh` 로 다시 받아 응답·요청 쿠키에 굽고, 갱신이 401 · 400 이면 쿠키를 지우고 `/login?expired=1` 로 보낸다. 그 밖의 실패(api 미기동 · 5초 시간 초과 · 429 · 5xx)는 접속이 끝났다고 단정하지 않고 쿠키를 둔 채 로그인 필요 화면과 만료 안내에서는 `/login?unavailable=1` 로 보낸다(그 밖의 공개 화면 `/login` · `/password-reset` · `/email-find` 는 그대로 연다). `/login?unavailable=1` 도 만료 안내처럼 갱신에 성공해야 로그인으로 친다 — 남은 액세스 토큰만 보면 `/home` 으로 튕겨 다시 401 → 만료 안내를 돈다. `/login?expired=1`(서버 컴포넌트가 401 을 받거나 세션을 못 읽으면 이리로 보낸다)에서는 갱신을 해 보고 정말 끝났을 때(401 · 400)만 쿠키를 지운다 — 살아 있으면 다시 굽고 `next`(없으면 `/home`)로 보낸다. 주소만으로 지우면 다시 로그인한 뒤 뒤로 가기 · 새로 고침이나 남이 건 링크로 접속이 끊긴다. 읽히지 않거나 모양이 다른 `account` 쿠키는 세션으로 치지 않고 지운다 — 판정은 화면의 `getSession` 과 같은 `parseAccountCookie` 다. 로그인 필요 경로 판정도 여기서 하되, 화면·액션은 `requireSession()` 을 따로 거친다. 갱신이 401 · 400 이거나 account 쿠키가 손상돼도 로그인 없이 여는 화면(`/login` · `/password-reset` · `/email-find`)은 쿠키만 지우고 그대로 연다 — 다른 기기에서 비밀번호를 바꿔 접속이 끝난 직원이 재설정으로 바로 가게 한다. `/design` 과 그 아래 · 정적 파일은 빼고 돈다. 로그인 화면(`/login` · 만료 안내 · 확인하지 못함 안내)으로 보낼 때는 보던 경로 + 쿼리를 `next` 로 싣고(홈이면 싣지 않음), 로그인돼 있는데 `/login` 이면 `next` 로 보낸다 — 만료 안내에서 갱신해 보니 살아 있던 경우도 같다(WHALEERP-166). 로그인이 필요한 화면으로 통과시키는 요청에는 지금 경로를 `x-staff-path` 헤더로 넘긴다(브라우저가 보낸 값은 덮어씀).
* `src/lib/api.ts` - whale-erp-api 호출 틀(`API_BASE_URL`, `request`, `ApiError`, 요청·응답 타입 `Schemas`). `ApiError` 는 상태 · 메시지와 함께 JSON 본문(`body`)을 들고 있어 메시지 밖의 칸(이메일 찾기 429 의 `lockExpiresAt`)을 읽을 수 있다. `request` 는 `json`·`accessToken`·`revalidate`(enum 처럼 모두에게 같은 응답만 캐시)·`timeoutMs`(기본 10초, 본문을 다 읽을 때까지) · `clientIp`(있으면 `X-Forwarded-For` 로 보냄) 옵션을 받는다. api 에 닿지 못하면(연결 실패 · 시간 초과) fetch 의 TypeError 대신 `NetworkError` 를 던진다 — 호출하는 쪽은 TypeError 로 가르지 않는다(코드 결함까지 연결 실패로 숨는다). 5xx · 연결 실패는 여기서 `console.error` 로 남기고, 부른 쪽이 예상하지 못한 4xx 는 `logUnexpected` 로 남긴다. `API_BASE_URL` 이 비었거나 주소가 아니면 바로 멈춘다. 처리하지 못한 서버 오류는 `src/instrumentation.ts` 의 `onRequestError` 가 digest 와 함께 남긴다. 같은 파일의 `register` 는 서버가 뜰 때 `API_BASE_URL` · `TRUSTED_PROXY_HOPS` 를 확인해 잘못되면 바로 멈춘다.
* `src/lib/api-types.d.ts` - `pnpm openapi:types`(`scripts/openapi-types.mjs`)가 api 의 `openapi/openapi.json` 으로 만든 타입. api 위치는 `WHALE_API_DIR`(기본 `../whale-erp-api`).
* `src/lib/session-cookies.ts` · `session.ts` - httpOnly 쿠키 `access_token`(14분 — 15분짜리 JWT 보다 1분 먼저 끝내 proxy 가 미리 갱신한다) · `refresh_token`(api 가 준 만료까지, 회전 없음) · `account`(로그인 응답의 계정 JSON — 로그인한 순간의 값이고 갱신해도 바뀌지 않는다. 갱신 응답에 계정이 없고 api 에 계정 조회가 없어서다. 상태처럼 바뀌는 값은 화면의 API 로 다시 읽는다) · `device_id`(로그인의 `deviceIdentifier`, 로그아웃해도 남김). `saveLogin` · `getSession` · `requireSession` · `clearSession` · `getDeviceId` · `authedRequest`(401 이면 `/login?expired=1`). 만료 안내로 보낼 때 proxy 가 넘긴 `x-staff-path` 를 `next` 로 붙인다. `src/lib/login-return.ts` - 로그인 뒤 돌아갈 곳(WHALEERP-166). `safeNextPath` 는 `/` 로 시작하는 이 사이트 경로만 받는다 — `//` · `\` · 제어 문자 · 다른 출처로 풀리는 값 · 정규화하면 `//` 로 시작하는 값(`/.//evil.com`)과 로그인 없이 여는 화면은 버린다. `next` 는 주소에 실려 남이 만든 링크로도 들어오므로 로그인 화면이 거르고 로그인 액션이 숨은 칸 값을 다시 거른다. 맞지 않으면 `/home`. 로그아웃은 돌아갈 곳을 기억하지 않는다. 쿠키에 두지 않아 공용 기기에 남지 않고 탭마다 따로 돈다.
* `src/lib/auth.ts` - 직원 계정 인증 API(`login` · `refreshAccessToken` · `logout` · `requestPasswordResetPin` · `verifyPasswordResetPin` · `resetPassword` · `findEmails`). 모두 직원의 실제 접속 IP 를 받아 `X-Forwarded-For` 로 넘긴다. `src/lib/client-ip.ts` - `clientIpFrom(headers)`. api 는 요청 제한을 IP 로도 세는데(api PR #10 `TRUST_PROXY`) 이 앱은 Next 서버가 대신 부르므로, 넣지 않으면 모든 직원이 한 버킷을 쓴다. Next 는 들어온 `X-Forwarded-For` 가 없을 때만 소켓 주소를 채우고 있으면 그대로 두므로(지어낼 수 있다), `TRUSTED_PROXY_HOPS`(Next 앞의 프록시 수, 기본 0 = 로컬 개발. 운영에서 비었거나 0 이면 기동을 막는다) 만큼 오른쪽에서 센 항목 하나만 주소로 확인해 넘긴다(타입 `ClientIp` 라 들어온 헤더 값을 그대로 넘길 수 없다). 프록시 뒤인데 고르지 못하면 프로세스마다 한 번 경고를 남긴다. 운영 값은 인프라 구성으로 정한다. `src/lib/enums.ts` - `getEnum(name)`(한 시간 서버 캐시, 응답에 그 이름이 없으면 오류) · `getEnumOrEmpty`(5xx · 연결 실패면 빈 목록, 404 등 결함은 던짐) · `labelOf`.
* `src/lib/password-reset.ts` - 재설정 쿠키(`readPasswordReset` — 모양이 다르면 없는 것으로 봄 · `savePasswordReset` · `clearPasswordReset`), `PIN_VALID_MS`(10분 한 시계. 화면의 남은 시간 · 만료 · 다시 받기는 `readPinClock` 이 내려 준 서버 시각에 맞춰 센다 — 발급 시각이 서버 시계라 휴대폰 시계와 바로 비교하면 어긋난다) · `PIN_RESEND_MS`(1분 — api 가 그 안의 재요청을 보내지 않고 204 로 답해 화면이 막는다), `maskEmail`(@ 앞 처음 2글자 + 마지막 1글자, 3글자 이하는 첫 글자만 — 앱 공통 LOGIN-9 규칙). 같은 이메일로 1분 안에 다시 핀을 요청하면 api 를 부르지 않고 앞 핀 화면으로 돌려보낸다. `src/lib/password-rules.ts` - api `validateNewPassword` 와 같은 규칙의 안내용 검사(판정은 api).
* `src/lib/payslips.ts` - 급여명세서 타입(`Schemas` 의 `MyPayslip*Dto`)과 `getPayslips(filter)`(api `GET /me/payslips?storeId&year` → `{ thisMonth, stores, items }`, 받은 날 최신순) · `getPayslip`(`GET /me/payslips/:id`, 404 면 null) — 둘 다 `authedRequest`(WHALEERP-330). api 가 발송된 · 만든 지 3년 안의 내 명세서만 주므로 화면에서 다시 거르지 않는다. 화면 규칙 · 문구는 순수 함수 모듈 `src/lib/payslip-rules.ts`(`itemAmount` — 관리자 수정값 > 시스템 계산값, 둘 다 없으면 0 · `isItemShown` — 관리자 화면(front `src/lib/payslips.ts`)과 같은 규칙: 원천징수 줄(`WITHHOLDING`, 사업소득세(3%) · 지방소득세(0.3%) 두 줄)은 `isWithholdingApplied` 일 때만, 그때 기본 공제의 `INCOME_TAX` · `LOCAL_INCOME_TAX` 는 뺀다 · `historyEntries` · `isResent` · 날짜 문구 · `parsePayslipId` · `filterYears` · `parsePayFilter`)에 있다. 테스트는 `src/lib/payslip-rules.test.ts`. 데모에 있던 줄마다 계산 근거(PAY-3) · 「해당 없음」 · 「· 정정됨」은 api 에 값이 없어 보이지 않는다. 화면 합계는 줄을 다시 더하지 않고 저장된 `grossPayAmount` · `totalDeductionAmount` · `netPayAmount` 를 보인다.
* `src/lib/email-find.ts` - 이메일 찾기 입력 정리(`normalizeBirthDate` — 숫자 8자리에 하이픈을 넣음, `normalizePhone` — 하이픈 · 공백을 지움, 판정은 api)와 `lockExpiresAtOf`(429 가 번호 잠금이면 해제 시각, 요청 제한이면 null).
* `src/app/design/` - 디자인 가이드 견본 화면(`/design`, 색인 제외). 맨 위 링크 줄에서 화면 목업으로 간다.
* `src/app/design/(mockup)/` - 인증·API 없이 UI 만 보여 주는 화면 목업(`/design/login`, `/design/home`, `/design/check-in`, `/design/attendance`, `/design/work`, `/design/pay`, `/design/notification-settings` …). 모바일 앱에 들어갈 화면이라 폭 100% 로 그린다.
* `docs/demo/` - 직원 근무 앱 클릭 데모. 관리자 웹 데모(whale-erp-front `docs/demo`)와 같은 정적 HTML 생성기다. `node docs/demo/build.mjs` 가 `src/pages/<화면>/index.mjs`(화면 하나 = 목업 한 장)를 `<화면>/index.html` 로 내고, 앱과 같은 Tailwind 로 `docs/demo` 를 훑어 `assets/staff.css` 를 만든다(토큰은 `src/app/globals.css` 를 그대로 읽음, 자원 주소에 내용 해시). 화면은 `src/ui.mjs`(공통 부품 `src/components/common` 을 HTML 문자열로 옮긴 함수, 클래스 문자열이 같아야 한다)로만 그린다. 같은 화면의 상태는 상태마다 블록을 두고 `assets/staff.js` 가 주소 `#상태` 로 보이고 숨긴다. 화면 밖 오른쪽 위 상태 전환 도구, 시트·토스트·탭·스위치·체크칸도 `staff.js` 한 파일이 `data-*` 단서로 붙인다. 화면 둘 이상이 쓰는 조각은 DESIGN.md 「데모 조각」 절. 하단 메뉴는 다섯 칸(홈·근무·출퇴근·급여·내 정보, 2026-10-08 재영 결정 — Figma 는 네 칸), 출퇴근 칸은 출퇴근 등록으로 간다. 가짜 값만 쓰고 API 는 부르지 않는다. 화면은 `login`·`join`·`home`·`work`·`check-in`·`attendance`·`contract`·`tax`·`pay`·`notify`·`me`. 미니 nginx 8081 은 `/demo/` 를 이 폴더로 잇는다. 계획은 `docs/plans/2026-10-08-직원-근무-앱-데모.md`.
* `src/components/common/` - 직원앱 공통 컴포넌트. 화면은 `StaffRoot` 로 감싼다. `Dock` · `Alert` · `DangerButton` 은 데모 조각을 참고해 새로 올린 것이다.
* `public/` - Static assets served at the site root. Figma 아이콘은 `public/icons/`.
